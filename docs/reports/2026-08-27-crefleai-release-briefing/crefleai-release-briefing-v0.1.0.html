기존 배포 구조

기존 서비스는 하나의 Docker Compose 서비스로 실행된다. 컨테이너는 FastAPI 서버, 관리자 화면과 Chat 정적 웹, 로컬 추론 워커 제어 기능을 함께 포함한다. 데이터는 /home/crefleai/data에서 /app/data로 마운트되고, GPU는 Compose의 gpus: all 설정으로 컨테이너에 전달된다.

이번 개발로 변경된 부분

관리자 모니터링 추가

관리자 API에 GET /api/admin/metrics가 추가되었고, 관리자 화면에 /admin/monitoring 페이지가 연결되었다. 운영자는 브라우저에서 GPU 사용률, VRAM 사용량, 데이터 디스크 사용량, 최근 요청 처리량을 확인할 수 있다.

신규 모니터링 지표
지표수집 방식운영 의미
GPUNVML(nvidia-ml-py)GPU 사용률과 VRAM 압박 확인
DiskCREFLEAI_DATA_DIR 대상 disk usage모델 파일과 DB가 위치한 데이터 볼륨 용량 확인

시스템 지표는 애플리케이션 lifespan에서 백그라운드 샘플러가 주기적으로 수집한다. GPU 지표 수집 실패는 전체 API 장애로 전파하지 않고, GPU 항목만 수집 불가로 표시한다.

Chat 테스트 화면 안정화

Chat 화면은 System 프롬프트와 Temperature를 localStorage에 저장하도록 개선되었다. 저장된 Temperature가 숫자가 아니거나 허용 범위 0~2를 벗어나면 기본값 0.7로 복구한다.

모델의 context_length를 GET /v1/models에서 조회해 컨텍스트 사용량을 표시한다. 실제 응답 usage가 있는 경우 실제 토큰 수를 사용하고, 없거나 현재 대화와 맞지 않으면 문자 수 기반 보수 추정값을 표시한다.

Harmony 출력 처리 개선

gpt-oss Harmony 형식의 추론 과정과 최종 답변을 분리해 보여주며, 종료 토큰이 본문에 노출되지 않도록 후속 버그가 반영되었다. 채널 진입 판정도 특정 패턴에만 묶이지 않도록 일반화되어 형식 변화에 대한 내성이 높아졌다.

배포 구성 영향

Compose 서비스 수와 포트 구조는 변경되지 않았다. 다만 GPU 지표를 보려면 운영 서버의 NVIDIA 드라이버와 NVIDIA Container Toolkit, 그리고 Compose의 GPU 전달 설정이 정상이어야 한다. 해당 조건이 충족되지 않으면 관리자 화면의 GPU 카드만 수집 불가로 표시된다.

배포 전 체크리스트

  1. server/pyproject.toml 버전과 이미지 태그를 이번 배포 버전으로 확정한다.
  2. GPU 서버에서 전체 Docker 이미지를 빌드하고 registry에 push한다.
  3. 운영 .env에 CREFLEAI_IMAGE_TAG, CREFLEAI_JWT_SECRET, 관리자 초기 계정 값을 설정한다.
  4. docker compose up -d 후 docker compose ps에서 healthy 상태를 확인한다.
  5. 관리자 로그인 후 /admin/monitoring에서 Disk, 요청 지표, GPU 지표 수집 상태를 확인한다.
  6. 모델 1개를 다운로드·서빙하고 Chat 화면에서 스트리밍 응답, Harmony 표시, 컨텍스트 사용량 표시를 확인한다.

잔여 리스크

  • 테스트 환경의 JWT 테스트 키가 짧아 경고가 발생한다. 운영에서는 32바이트 이상 secret 사용이 필수다.
  • GPU 지표는 NVML 노출에 의존한다. 운영 서버의 NVIDIA Container Toolkit 설정이 빠지면 GPU 카드가 수집 불가로 보인다.
  • 현재 버전은 여전히 단일 Compose 서비스 구조다. Gateway·Worker 분리는 별도 아키텍처 전환 과제로 남아 있다.
