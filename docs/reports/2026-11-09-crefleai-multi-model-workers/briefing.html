01 · 개요 — 쉽게 말하면

주방이 하나뿐인 식당을, 주방 여러 개인 식당으로

CrefleAI를 식당에 비유하면, 게이트웨이는 주문을 받는 홀 매니저, 워커는 요리하는 주방, 모델은 메뉴, GPU는 주방 크기입니다.

지금

주방 1개, 메뉴 1가지

  • 한 번에 메뉴 하나만 만들 수 있어요.
  • 메뉴를 바꾸려면 주방 문을 닫고 재료를 갈아야 해요. 그동안 손님은 기다려요.
  • 주방이 커도(GPU 여러 개) 나눠 쓸 수 없어요.
→
바뀐 뒤

주방 여러 개, 메뉴 여러 가지

  • 홀 매니저가 주문서(모델 이름)를 보고 맞는 주방으로 보내요.
  • 새 주방은 매니저가 준 등록증을 들고 와서 스스로 등록해요.
  • 주방이 메뉴에 비해 너무 작으면, 그 메뉴는 아예 못 열게 막아요.

동시 서비스

범용·코딩·대형 모델을 함께 띄우고, 사용자는 model 값만 바꿔 호출합니다.

GPU·서버 분리

같은 PC의 GPU별로, 또는 다른 GPU 서버에 워커를 따로 띄웁니다.

사양 보호

모델별 최소·권장 사양을 보여주고, 최소 사양에 못 미치면 실행을 막습니다.

02 · 플랫폼 구조 — 기존

지금: 컨테이너 하나에 모든 것이 묶여 있다

게이트웨이가 같은 컨테이너 안에서 워커 하나를 직접 띄우고, 고정 주소(127.0.0.1:8001)로만 요청을 보냅니다.

모델 1개만 서비스워커 매니저가 항상 0개 또는 1개의 워커만 관리합니다.
교체하면 중단다른 모델을 쓰려면 기존 워커를 내리고 새로 로드해야 합니다.
GPU·서버 확장 불가컨테이너에 GPU 전체가 묶여 모델별·서버별 배치가 안 됩니다.

03 · 플랫폼 구조 — 변경안

변경 후: 게이트웨이는 길잡이, 워커는 어디서든

워커는 스스로 등록하고, 게이트웨이는 요청의 model 값을 보고 준비된 워커로 보냅니다. 기존 방식의 로컬 워커도 등록된 워커 하나로 함께 운영합니다.

04 · 무엇이 바뀌나

한눈에 비교

구분기존변경 후
동시 서비스 모델1개워커 수만큼 (워커 1개 = 모델 1개)
워커 위치게이트웨이 컨테이너 안같은 PC의 GPU별 · 다른 GPU 서버 · 호환 모드 로컬
워커 연결고정 주소 127.0.0.1:8001워커가 등록 토큰으로 스스로 등록, 게이트웨이가 워커 주소로 요청
모델 선택관리자가 교체 (서비스 중단)사용자가 model 값으로 선택, 교체 없음
같은 모델 동시 요청워커 1개가 하나씩 처리, 나머지는 그 워커만 기다림빈 워커로 바로 분산, 모두 바쁘면 요청 순서대로 먼저 끝난 워커가 받음
장애 영향워커가 죽으면 전체 추론 중단해당 모델만 영향, 다른 모델은 계속 서비스
사양 확인없음 (로드 실패로 알게 됨)실행 전에 GPU 메모리 판정, 최소 미달 시 차단
외부 API변경 없음 — 같은 주소·토큰·요청·오류 형식 (인스턴스 지정은 관리자 점검용만)

워커가 서비스에 붙는 4단계

등록 토큰 발급

관리자가 관리자 화면에서 1시간짜리 등록 토큰을 발급합니다.

워커 실행

운영자가 게이트웨이 주소·등록 토큰·모델 ID·GPU를 넘겨 워커를 실행합니다.

사양 판정

워커가 할당된 GPU의 남은 메모리를 모델 최소 사양과 비교합니다. 모자라면 여기서 멈춥니다.

자가 등록 · 서비스

모델을 로드하고 스스로 등록합니다. 받은 자격 증명으로 재시작해도 자동 재연결됩니다.

05 · 목표 및 검증 지표

무엇이 되면 성공인가

명세의 성공 기준(SC-001~012)을 여섯 가지 목표로 묶었습니다. 모두 실제 GPU 환경에서 시험해 확인합니다.

2+동시에 서비스하는 모델 수
≤ 20%동시 호출 시 첫 응답 지연 증가
99%워커 하나가 죽어도 다른 모델 성공률
30초고장 워커 제외·복귀까지
0건사양 미달 워커 등록 · 토큰 재발급
목표쉬운 말로기준확인 방법
동시 서비스모델 두 개를 동시에 불러도 서로 거의 안 기다린다
SC-001 · SC-002		 지연 증가 ≤ 20%모델별 단독 호출과 동시 호출의 첫 응답 시간 비교. GPU별 워커 2개 + 다른 서버 워커 1개 구성
공정한 분배빈 주방이 있으면 바로 거기로, 다 바쁘면 먼저 온 손님부터 먼저 비는 주방으로
SC-011 · SC-012		 빈 워커 두고 대기 0건
순서 일치 100%		같은 모델 워커 2개에 사용자 5명 동시 요청을 반복하며, 대기 발생 시점과 워커 전달 순서를 기록해 요청 순서와 비교
장애 격리한 주방에 불이 나도 다른 주방은 계속 요리한다
SC-003 · SC-004		 성공률 ≥ 99%
30초 내 제외·복귀		워커 하나를 강제 종료·재시작하며 다른 모델에 요청을 계속 보내 성공률과 상태 변화 시간 측정
기존 사용자 무변경쓰던 프로그램을 고치지 않아도 된다

쉬운 운영새 주방을 붙이는 데 오래 걸리지 않는다
SC-006 · SC-010		 워커 추가 ≤ 15분문서 절차대로 새 워커를 추가해 서비스 목록 노출까지 시간 측정(모델 파일 준비 제외). 관리자 화면만으로 실행 가능 여부 판단
